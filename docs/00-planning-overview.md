## 1. 项目定义

- **项目名称**：知悉 LifeGuard
- **英文名称**：LifeGuard - Personal Life Guardian
- **定位**：个人生活权益与风险智能管家
- **赛道**：LifeHack 生活娱乐
- **口号**：让每一份消费凭证都有价值，让每一个重要期限都不被遗忘。
- **核心闭环**：材料上传 → 信息识别 → 用户确认 → 风险分析 → 期限管理 → 行动建议 → 完成记录。

知悉不是通用聊天机器人，也不是在凭证图片上叠加日历。它把非结构化生活材料转化为**有证据、可确认、可执行、可复盘**的个人事项。

## 3. 推荐架构摘要

### 竞赛主版本：Qoder Sites 全功能云版

- **前端**：Vue 3 + Vite + TypeScript + Tailwind CSS + Pinia + Vue Router + ECharts。
- **服务端**：Qoder Sites 单个 TypeScript Edge Function，承载业务 API、权限、规则引擎、数据库与 Storage 访问、模型代理。
- **数据**：Qoder Sites Function-owned Database；私人附件进入受权限保护的 Storage，不进入前端构建产物。
- **识别**：PDF 文本提取/OCR 与可配置大模型均通过服务端适配器调用；密钥仅存在 Sites Secrets。自托管 PaddleOCR/FastAPI 作为独立识别服务，不假设能运行于 Qoder Sites。
- **业务正确性**：规则引擎计算日期、风险、周期支出、异常候选和统计；AI 不直接决定金额、截止日期、节省金额或完成状态。
- **提醒边界**：首版提供打开应用即可见的站内雷达；邮件、系统推送和后台定时提醒需要额外调度服务，未接入前不宣称已实现。

### 无后端降级版：真实本地版，而非功能伪装

- 同一 Vue 前端，IndexedDB 持久化，浏览器内 PDF 文本提取和可验证的规则解析。
- 手工录入、编辑、确认、期限雷达、行动模板、完成记录、统计和演示模式完整可用。
- OCR 只有在浏览器运行时真实加载并识别成功时才标记可用；模型抽取、跨设备同步、服务端通知和云端附件不可用时明确标注。
- 本地数据不出设备，清除浏览器数据可能导致丢失，必须提供导出与清空确认。

### 可选独立 AI 识别服务

若竞赛部署需要中文扫描件的高质量 OCR，可将 **Python + FastAPI + PaddleOCR** 部署到支持 Python 的独立环境。Qoder Function 仅调用固定、受认证、限时的服务地址。该服务是可选基础设施，不能把它未部署时的界面表现包装成云端识别成功。

## 4. 需要用户确认的架构决策

1. 是否接受 **Qoder Sites Edge Function（TypeScript）替代在 Sites 内运行 FastAPI**，并将 FastAPI 仅作为可选外部 OCR 服务？
2. 竞赛主版本是否采用“**云端账户数据 + 私人附件 Storage**”，还是优先采用完全本地、无账户版本？
3. 是否可提供至少一个服务端模型接口及一个 OCR 方案？若不能，是否接受“规则/手工确认可用、AI 能力明确降级”的真实交付？

未收到确认前，不初始化前后端项目，不申请云资源，不编写业务实现。

## 5. 全局验收底线

- 每个可见按钮都连接到真实业务动作或明确说明不可用原因。
- 缺失、冲突、低可信字段显示“待确认”，绝不自动补造。
- 未确认识别结果不进入正式期限、支出和风险统计。
- 所有日期、金额、风险排序和统计都可追溯到记录与规则。
- “节省金额”只来自完成记录中的用户确认值；演示数字只存在于明确隔离的演示工作区。
- 私人材料默认私密；前端产物不包含模型密钥、数据库凭证或真实上传材料。
- 完整主流程、异常输入、空数据、重复材料、并发修改和移动端正向路径均有测试证据。
