# 知悉 LifeGuard 测试方案

## 1. 目标与证据原则

测试不仅验证“页面能打开”，还要证明业务闭环、数据真实性、权限边界和降级行为。每份测试报告将结果分为：

- **单元/组件验证**：纯规则、UI 交互和 schema。
- **本地集成验证**：真实业务 handler + 无凭证假适配器。
- **部署集成验证**：真实 Sites Function、Database、Storage、身份和第三方接口。
- **人工验收**：视觉、可访问性、材料识别质量与评委主路径。

本地 fixture 通过不能替代云端权限或 Provider 集成；HTTP 200 不能替代业务响应与浏览器结果；代码存在不能标成测试通过。

## 2. 测试环境与数据

| 环境 | 数据/依赖 | 用途 |
| --- | --- | --- |
| 纯单元 | 固定时钟、固定 ID、内存记录 | 日期、金额、风险、状态、模板、统计 |
| 前端组件 | Vue Test Utils、拦截 API | 表单、确认、错误和可访问交互 |
| 本地 Function | 真实 handler、内存 DB/Storage/身份 | 路由、权限逻辑、幂等、恢复和契约 |
| 浏览器 E2E | Playwright、本地隔离数据 | 完整用户主路径和移动端 |
| 部署测试 | 专用测试 Site、两个测试账户、一次性私有对象 | 真实身份、数据库、Storage、模型/OCR |
| 识别评测 | 虚构或明确授权且匿名化的材料与人工标注 | OCR/字段抽取质量、证据和待确认行为 |

禁止把真实私人凭证放进源码、公开测试集、日志或演示 fixture。测试账号和上传对象只用于授权测试，完成后仅清理本次创建的对象。

## 3. 单元测试矩阵

### 3.1 日期与期限

| 用例 | 预期 |
| --- | --- |
| 2028-02-29 | 闰日合法 |
| 2027-02-29、2026-02-30、2026-13-01 | 拒绝，不自动滚动日期 |
| 年付续费从 1 月 31 日推进 | 使用明确月末规则，结果稳定且有解释 |
| `start_on > end_on` | 阻止确认 |
| 截止日昨天/今天/明天/第 3/4/7/8/14/15/30/31 天 | 风险分档与排序边界准确 |
| `Asia/Shanghai` 与 UTC 交界 | 以用户时区日历日判断“今天” |
| 修改用户时区 | 提示重算结果，不修改已保存日历日期 |
| 无政策依据的购买日期 | 不自动推导退货截止日 |
| 有明确来源日期、周期与规则 | 保存衍生依据并正确计算 |

### 3.2 金额与币种

- 字符串转最小货币单位：0、0.01、199.00、大额上限、前导零。
- 拒绝 NaN、Infinity、指数形式、多余小数位、负数、超安全整数和混入文字的金额。
- 累计使用整数，验证 0.1 + 0.2 类场景无浮点误差。
- CNY、USD 等分别汇总，不进行无汇率换算。
- `null`、0 和缺失节省金额含义不同。
- 每月等值按明确舍入规则展示，原始周期金额保持不变。

### 3.3 风险与统计

- 每个 U/I/O/A 因子边界、封顶 100、稳定同级排序。
- 未确认字段不生成正式期限，不参与风险和支出。
- 同一事项多个期限只计一次当前主风险。
- 无暴露金额只显示原因，不计入潜在金额。
- 已完成/已忽略事项不进入当前待办，恢复后重新进入。
- 统计查询失败返回“不可用”，不得映射成 0。
- 无历史快照日期留空；不能根据当前事项倒造历史风险。
- 用户估算与实际退款等节省口径分组。

### 3.4 状态机与行动模板

- 非法状态迁移被拒绝，如上传失败直接变识别成功。
- 待确认 → 进行中必须有用户确认事件。
- 步骤勾选可逆；步骤全部完成不自动完成整个事项。
- 完成必须有结果记录；恢复保留历史。
- 六类规则模板在模型关闭时仍生成正确结构。
- 模板缺少字段时显示补充提示，不生成虚假政策、链接或联系方式。
- 模板更新不无意清空既有步骤状态。

### 3.5 订阅与异常

- 日/周/月/年和自定义周期推进，跨越多个漏算周期后落到未来日期。
- 已取消或未启用自动续费的项目不继续推进。
- 月付 10 元与年付 120 元每月等值一致。
- 相同标准化服务名产生重复候选；不同用途可由用户裁定。
- 相似但不同服务不自动判重复。
- 0/1/2 笔实际扣款不做异常判定，3 笔及以上才运行规则。
- 金额突增、间隔异常、正常浮动、不同币种、重复扣款导入分别验证。
- 预测续费不进入实际支出。

## 4. API 与数据集成测试

### 4.1 路由与 schema

- 未知路径 404、错误方法 405、非法 JSON/Content-Type/超大正文 400 或 413。
- 成功响应也通过 schema；缺字段、错误类型和额外危险字段被处理。
- GET 无业务写入；原始上游异常、SQL、堆栈、内部 URL 不返回浏览器。
- 分页边界、空页、稳定排序、精确 count 大于当前页大小。
- 请求取消和旧响应不会覆盖新筛选/新事项。

### 4.2 身份与对象权限

- 匿名访问私有路由返回 401/403，公开健康检查不含私人数据。
- 账户 A 不能读取、修改、完成、删除账户 B 的事项、字段、行动、订阅和完成记录。
- A 不能使用 B 的 material ID、storage path、signed URL 请求或 ownerId。
- 浏览器伪造 `owner_id`、用户上下文、平台 header 不被信任。
- 数据库所有查询都带 owner 条件；影响行数为 0 时不返回成功。
- 部署后验证 Provider 直连和备用入口，不只验证站点域名返回 403。

### 4.3 幂等与并发

- 同一上传/事项/识别/完成幂等键与相同载荷返回原结果。
- 同键不同载荷返回冲突，不覆盖原记录。
- 响应丢失但写入已提交时，对账只产生一条记录。
- 未知结果不自动重放 POST/PATCH/DELETE。
- 两个标签页用同版本编辑，第一个成功，第二个得到冲突并保留输入。
- 列表读与写同时发生时，旧读响应不吞掉最新刷新。
- 上传确认响应丢失时可按原上传意图恢复，不重复生成材料。

### 4.4 Storage 与识别任务

- 上传签名前验证用户、路径、大小和类型；上传后再验证实际对象。
- Content-Length 缺失或错误时仍按真实字节限制，不只看声明值。
- 损坏 PDF、加密 PDF、空文件、伪装 MIME、超限页数进入明确失败状态。
- 路径穿越、原始文件名注入、覆盖他人对象和未授权删除被拒绝。
- 签名下载 URL 不进入日志；过期后需重新授权签名。
- 外部任务 pending/running/succeeded/failed/timeout 均可恢复，轮询有上限。
- Storage 成功但元数据失败、元数据成功但识别失败等部分状态不伪装整体成功。

## 5. OCR 与信息抽取评测

### 5.1 评测集

首版建立至少 60 份合成或授权匿名材料，覆盖六类事项，并包含：

- 清晰/倾斜/模糊/低对比图片，截图与拍照件。
- 文本 PDF、扫描 PDF、多页 PDF、表格和混合排版。
- 多币种、中文金额、不同日期格式、缺失字段和冲突字段。
- 损坏/加密/超限文件作为负例，不计入识别准确率分母时单独报告。

人工标注字段真值、证据页码和原文区间。训练/提示词调参集与最终评测集分开，避免用同一批样本宣称泛化能力。

### 5.2 指标

- 字段级 exact match 与规范化 match，按事项类型分别报告。
- 金额、日期和截止日单独报告错误，不用其他字段高分抵消关键错误。
- 证据定位成功率：能否定位真实原文；grounding 与字段语义正确率分开。
- 待确认覆盖率：无真值/无法识别字段是否正确保持 null + pending。
- 幻觉率：材料无依据却生成确定值的字段比例。
- 人工修订率、平均处理时长、失败率和成本（若有）。
- OCR 分数、模型分数与真实正确率分开，不将 confidence 当准确率。

### 5.3 识别质量发布门槛

- 所有测试样本中，无依据字段必须进入待确认；不得自动进入正式期限。
- 非法金额/日期即使模型返回高 confidence 也被业务校验拦截。
- 任一抽取失败可手工修正并完成闭环。
- 规则与模型输出有明确来源，规则备用结果不标成 AI。
- 质量阈值在首轮基线测量后冻结；不得为通过测试而删除困难样本或修改真值。

## 6. 浏览器端到端场景

### E2E-01 手工完整闭环

新建退货事项 → 输入非法日期并看到错误 → 修正确认 → 首页出现今日/近期事项 → 打开行动模板 → 勾选步骤 → 复制话术 → 提交完成记录 → 待办减少、历史与节省按输入更新 → 刷新后保持。

### E2E-02 真实材料闭环

上传授权测试图片/PDF → 观察真实处理状态 → 候选字段至少一个待确认 → 对照证据修订 → 确认生成事项 → 后续雷达、行动、完成均使用修订值。

### E2E-03 识别降级

关闭模型/OCR 或使其超时 → 页面明确未配置/失败 → 不出现预置“识别结果” → 规则或手工路径仍可完成。

### E2E-04 重复与异常输入

重复上传同文件 → 显示已有材料与选择；上传空图、坏 PDF、超限时给出可恢复错误；重复点击提交只创建一条；相似业务记录只提示不自动合并。

### E2E-05 订阅

创建月付和年付 → 检查每月等值 → 创建续费期限 → 首页只计一次 → 相似服务出现重复候选 → 标记不同用途 → 添加三笔扣款后验证异常规则。

### E2E-06 空、错与冲突

全新账户空状态 → API 失败不显示 0 → 网络恢复后刷新 → 两标签页编辑冲突保留输入 → 写入成功但刷新失败不重复写入。

### E2E-07 演示隔离

载入演示 → 完成一个步骤 → 检查演示统计 → 退出后真实数据不变 → 重置演示恢复样例 → 私人上传前提示退出演示。

### E2E-08 移动端与可访问性

在窄屏完成上传、确认、今日处理和步骤勾选；仅用键盘完成手工闭环；检查焦点、弹层、标签、错误定位、200% 缩放、减少动态效果和图表文本摘要。

## 7. 安全与隐私测试

- 扫描 `dist`、Function 包、source map、网络请求和日志，无模型/OCR Key、数据库凭证、PAT 和签名 URL。
- OCR/模型文本包含 HTML、脚本、Markdown 图片和恶意链接时按纯文本安全渲染，防 XSS。
- 第三方 endpoint 不能由浏览器任意指定；固定地址、超时和响应大小限制有效。
- 文件名含 `../`、Unicode 控制字符、HTML 或超长内容时被规范化/拒绝，不影响存储路径。
- 上传 polyglot/伪装文件时进行内容级校验；私有文件不作为公开站点资源执行。
- 未授权下载、删除、覆盖、跨用户枚举 ID 均失败，错误不泄露对象是否存在以外的敏感信息。
- 日志和分析事件不含原始凭证文本、订单详情、地址、电话和私人附件。
- 清除演示、删除单条和清空账户作用域准确，不误删其他用户或真实工作区。
- 依赖漏洞和许可证在实施时扫描；开源借鉴不复制不兼容许可证代码。

## 8. 视觉、性能与兼容性

- 视口覆盖常见手机、平板和桌面；无关键横向溢出、遮挡和不可点击区域。
- 首屏以今日行动为核心，不出现无意义卡片墙、强渐变/发光和密集表格。
- 所有按钮检查实际 handler；不存在只有 toast 的“假保存/假识别/假删除”。
- 大列表有界加载，图表按需引入，慢网下保留可用表单与明确状态。
- 大文件处理不阻塞其他页面；OCR/WASM 若本地运行，记录内存、加载时长和失败行为。
- 当前 Chrome/Edge 完整测试，移动 Safari/Chrome 主路径测试；未覆盖浏览器不宣称全面兼容。

## 9. 部署验收

### 静态

- 生产 build 成功，首页、深链刷新、资源 Content-Type 和正文正确。
- 平台保留命名空间未被应用占用，缺失资源不会被 SPA HTML 200 误判。
- 发布包不含 dev、fixture、私人材料、`.env` 和 `_qoder`，大小在限制内。

### 动态

- 发布后通过真实同源 Function 完成一次读、一次写和一次刷新读取。
- 两个真实测试账户验证对象隔离；Provider 直连与备用入口单独检查。
- 一次性附件完成签名上传、实际验证、授权下载和清理。
- 已配置的模型/OCR 各完成一次真实请求；未配置项明确保持未验证/不可用。
- Desktop 静态预览只用于外观检查，不作为 Function 验收证据。

## 10. 发布通过与缺陷分级

- **阻断**：跨用户数据泄露、密钥暴露、伪造识别/统计、核心闭环不可完成、重复写入造成错误金额、未知写结果被盲目重放。
- **严重**：日期/金额错误、权限单点缺失、上传后无实际校验、完成记录丢失、演示污染真实数据。
- **一般**：可恢复错误提示不清、筛选/图表不同步、移动端局部操作受阻。
- **轻微**：不影响理解与操作的视觉问题。

发布要求阻断和严重缺陷为 0；P0 主路径全部有实际结果；识别评测集和规则边界结果留档；未验证云端能力必须在交付说明中列出，而不是默认为通过。

| 字段 | 内容 |
| --- | --- |
| 需求/用例 ID | 关联 PRD 与本测试矩阵 |
| 环境 | 单元/本地 fixture/部署实网/人工 |
| 构建与依赖版本 | 可复现提交、Node/Deno/Python/供应商契约 |
| 数据 | 合成/匿名授权/演示，禁止真实秘密 |
| 步骤与预期 | 可重复执行 |
| 实际结果与证据 | 断言、截图、日志安全摘要或请求 ID |
| 状态 | 通过/失败/未验证/被环境阻断 |
| 未验证边界 | 特别是权限、第三方、后台任务和识别质量 |
