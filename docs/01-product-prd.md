# 知悉 LifeGuard 产品需求文档（PRD）

## 1. 背景与问题

订单截图、电子发票、保修卡、会员续费、租赁合同和课程凭证分散在相册、PDF、聊天记录及不同平台中。现有工具通常只解决其中一段：OCR 只输出文本，日历只保存日期，订阅工具只记录周期扣款，通用 AI 对话只给建议。用户仍需自行判断字段是否可信、哪天必须处理、需要准备什么以及处理是否完成。

知悉要解决的是“**生活材料到权益行动之间的断层**”。产品价值不在于多保存一张图，而在于减少因遗忘退货、保修、取消续费、退租和课程有效期而产生的可避免损失。

## 2. 核心创新点

### 2.1 从“识别文本”升级为“证据驱动的事项”

每个关键字段保留来源材料、原文片段、识别方式、可信状态和用户修订记录。模型输出只是候选值，缺失或冲突就进入待确认，不用语言模型的流畅回答掩盖不确定性。

### 2.2 从“到期提醒”升级为“权益处置闭环”

事项不只包含日期，还包含风险依据、处置步骤、材料清单、沟通模板、步骤勾选和完成结果。用户能沿同一条路径完成“看见风险—理解原因—采取行动—记录结果”。

### 2.3 可解释的确定性风险与消费分析

期限、金额、周期和排序由可测试规则计算；大模型用于候选信息抽取和表达辅助。风险页面展示“为什么紧急”“潜在损失如何得出”，不使用无法解释的综合分数制造焦虑。

### 2.4 真实成果而非虚构战绩

潜在损失、已避免损失、周期支出和历史趋势分别采用不同口径。只有用户完成处置并确认金额后才记为“已节省”，并明确这是用户记录、非平台审计。演示数据独立标注，不混入真实统计。

### 2.5 隐私与可降级同时成为产品能力

云端模式采用私有附件、服务端密钥和逐条所有权校验；本地模式可真实完成手工闭环。AI/OCR 不可用时说明能力边界，而不是返回模拟识别结果。

## 3. 目标用户与关键场景

### 3.1 主要用户

- 网购频繁、需要跟踪退货和保修的学生与年轻职场人。
- 订阅多个内容、软件或健身服务，容易忘记续费日期的人。
- 有租房、课程、报名和缴费事项，希望统一管理期限的人。

### 3.2 核心场景

1. **退货**：上传订单截图 → 确认订单金额、购买日期和退货截止日 → 查看退货材料与沟通模板 → 勾选步骤 → 记录退款结果。
2. **保修**：上传保修卡/发票 → 确认产品、购买日和保修截止日 → 到期前查看售后材料清单 → 记录送修完成。
3. **订阅**：录入或识别续费凭证 → 确认金额、周期和下次续费日 → 发现同类别重复订阅候选 → 按取消步骤处理 → 记录实际取消与节省金额。
4. **退租**：上传合同 → 确认起止日期与需提前通知日 → 查看退租检查清单 → 逐项完成并归档结果。
5. **课程/缴费**：人工录入有效期和金额 → 时间轴提醒 → 完成报名、缴费或使用课程 → 留存完成记录。

## 4. 产品目标、非目标与衡量指标

### 4.1 首版目标

- 让用户在 3 分钟内完成一条材料或手工事项的确认。
- 首页直接回答“今天要做什么、为什么、可能损失什么、下一步是什么”。
- 完整跑通至少退货、保修、订阅、合同/课程四类事项。
- 云版与本地版都对实际能力作准确标注。

### 4.2 非目标（首版不做）

- 不替代律师、消费者协会或平台客服，不承诺退货、退款或维权结果。
- 不自动操作用户电商/银行/会员账户，不抓取需要用户密码的平台数据。
- 不做全量记账、资产管理和通用社交社区。
- 不做无业务上下文的常驻 AI 聊天窗口。
- 不在未接入调度服务时承诺邮件、短信或系统后台推送。
- 不用固定样本冒充 OCR、模型、数据库或真实节省成果。

### 4.3 产品指标（均由真实事件计算）

- 确认完成率：`已确认识别批次 / 已完成识别批次`，同时展示样本量。
- 行动完成率：`至少完成一个行动步骤的活跃事项 / 已生成行动计划的活跃事项`。
- 按期完成率：`截止前完成的事项 / 已到截止且已有结果的事项`，不将未完成事项排除后美化口径。
- 用户确认节省额：完成记录中的金额汇总，单独标注口径。
- 识别修订率：按字段统计人工修改比例，用于改进模板，不在前端展示虚假“AI 准确率”。

## 5. 范围与优先级

### P0：竞赛闭环必须有

- 图片/PDF 上传、格式与大小校验、私有保存、重复文件检测。
- 可配置识别适配器；无识别服务时支持手工录入和规则解析，并明确状态。
- 字段级候选值、证据、可信状态、用户编辑与确认。
- 退货、保修、续费、合同、课程、缴费六类事项。
- 今日事项、30 天时间轴、紧急排序、筛选和详情。
- 规则行动模板、材料清单、沟通文本、步骤勾选。
- 周期订阅录入、即将续费、月度折算和重复订阅候选。
- 待处理/近期到期/潜在损失/完成/节省统计，全部来自记录。
- 完成记录、空/错/加载状态、重复业务记录提示。
- 独立演示模式、一键载入、重置和退出。
- 桌面与移动端可用、重要字段可编辑、数据导出和删除。

### P1：闭环稳定后扩展

- 多笔实际扣款序列的周期检测与异常涨幅分析。
- 多材料合并为一个事项、字段级原文位置高亮。
- 模型辅助改写沟通文本、更多行动模板。
- 邮件/Web Push 等外部提醒（需真实调度和授权）。
- 跨设备同步、数据导入迁移、家庭成员共享（另行设计权限）。

### 明确暂缓

- 自动取消订阅、自动退货、自动支付或自动联系平台。
- 银行级账单聚合、复杂投资分析、公开材料市场。
- 未经人工确认的日期自动进入高风险提醒。

## 6. 核心业务对象与状态

### 6.1 材料状态

`上传中 → 待处理 → 识别中 → 待确认 / 识别失败`

- 上传失败不生成“识别成功”记录。
- 识别失败保留可删除的原始材料与可重试任务，允许改为手工录入。
- 同一文件再次上传时提示已有材料，由用户选择复用或保留副本。

### 6.2 事项状态

`草稿 → 待确认 → 进行中 → 已完成 / 已忽略`

- 新建或识别后的事项默认为待确认。
- 关键日期确认后才生成正式期限；未确认内容仍在“待确认”列表可见。
- 已完成事项保留历史，不参与当前待办数量。
- 已忽略必须记录原因，可恢复；忽略不等于删除。

### 6.3 行动步骤状态

`待处理 → 已完成`，可取消勾选并记录更新时间。步骤完成不自动等于整个事项完成；用户需选择结果并提交完成记录。

## 7. 功能需求

### 模块 1：智能材料识别

#### FR-101 上传与材料管理

- 支持 JPG、PNG、WebP、PDF；首版产品预算建议图片不超过 10 MiB、PDF 不超过 15 MiB 且不超过 20 页，实际上限取产品与部署环境较小值。
- 校验扩展名、声明 MIME、文件魔数和实际字节；拒绝空文件、加密 PDF、损坏文件和超出预算材料。
- 显示上传、处理、成功、失败、取消和重试状态；失败信息不包含密钥、内部地址或原始服务异常。
- 私人文件默认不可公开访问；下载需重新授权并使用短时签名地址。

#### FR-102 文本与候选字段抽取

- 文本型 PDF 优先提取文本；扫描页再进入 OCR，避免无意义的重复识别。
- 统一候选字段：订单号、事项名称、商家、金额、币种、交易日期、开始/结束日期、退货截止日、保修截止日、续费日、周期、合同日期和课程有效期。
- 返回结构化 JSON；每个字段包含候选值、来源、证据片段、可信分数或“不可评分”、确认状态。
- 模型分数不得直接宣称为校准准确率。证据缺失、字段冲突、格式非法或低于阈值时均为待确认。
- 不根据常识虚构平台退货政策；只有材料或用户明确提供规则时才计算衍生截止日，并保留计算依据。

#### FR-103 用户确认与修正

- 原文/材料预览与字段表单并排（移动端上下切换），突出待确认字段。
- 用户可修改所有重要字段，包括模型高置信字段；人工值标记为 `manual`。
- 确认前再次校验真实日历日期、金额和字段关系；保存后生成事项和期限。
- 保留原始候选与用户修订，不覆盖证据链。

**验收**：模糊截图中的不可读金额不得被自动填成确定值；用户修正后，雷达、行动和统计使用修正值。

### 模块 2：个人生活期限雷达

#### FR-201 首页工作面

首屏依次呈现：

1. 今日需要处理的事项及主行动按钮。
2. 未来 7/30 天期限时间轴。
3. 有金额依据的潜在损失提醒。
4. 生活风险趋势（按真实期限与完成记录聚合）。
5. 快速上传和手工新建入口。

#### FR-202 排序与筛选

- 默认按“已逾期且仍可处理、今天、未来日期、影响程度、更新时间”排序。
- 支持按类型、状态、时间范围、金额依据和关键词筛选；筛选条件可清除。
- 显示“剩余 3 天”“今天截止”等自然语言及完整日期，避免只显示相对时间。
- 无数据展示下一步动作，不生成示例风险填充真实首页。

#### FR-203 风险解释

- 每个风险显示来源期限、影响等级、金额依据和缺失信息。
- 风险评分只用于排序，展示为低/中/高/紧急和解释，不伪装成精确损失概率。
- 潜在损失仅在用户确认过暴露金额时显示；无法确定金额的事项显示“金额待确认”，不计入总额。

**验收**：同一组记录在相同时区与规则版本下排序稳定；修改截止日后，首页、时间轴和统计同步更新。

### 模块 3：AI 行动建议引擎

#### FR-301 可执行计划

按事项生成：

- 建议完成时间与下一步主行动。
- 有序步骤，可单独勾选。
- 材料清单，如订单号、发票、商品照片、序列号、支付凭证。
- 场景化沟通文本，可编辑、复制；复制成功有反馈。
- 注意事项与信息缺口，不编造平台入口、电话、政策或法律结论。

#### FR-302 规则优先、AI 辅助

- P0 使用版本化模板：退货、保修、会员取消、退租、课程、缴费。
- 模板仅使用已确认字段；缺失字段以“请补充……”呈现。
- AI 可改写语气或整理补充建议，但输出须通过结构化 schema、安全过滤和事实字段校验。
- AI 失败不阻断规则计划；页面标注“基础行动模板”而非“AI 已生成”。

#### FR-303 完成记录

- 完成时选择结果：已退货/已退款/已维修/已取消续费/已退租/已缴费/其他。
- 可填写实际结果、完成日期、用户确认节省金额和备注。
- 节省金额为 0 也允许保存；未填写不计入节省统计。
- 完成后保留时间线，可编辑结果或恢复事项，所有变更保留审计事件。

**验收**：关闭模型接口后，六类模板仍可生成、步骤仍可完成，统计能真实更新。

### 模块 4：隐形消费识别

#### FR-401 周期消费

- 支持从材料候选或手工录入商家、金额、币种、周期、下次续费日和状态。
- 周期支持月、季、年及自定义天数；月付/年付统一折算为“每月等值”，同时保留原始金额与周期。
- 月度折算仅用于比较，明确它不是实际当月扣款。
- 即将续费列表与期限雷达共享确认后的续费期限，不重复计数。

#### FR-402 重复订阅候选

- 先按标准化商家/服务名精确匹配，再按用户确认的类别给出“可能重复”。
- 候选必须展示匹配原因，由用户标记“重复”“不同用途”或“不确定”；不得自动取消或自动累计可节省金额。

#### FR-403 异常支出

- 只有具备同服务至少 3 笔实际扣款记录时才检测金额异常或周期异常。
- 金额变化、扣款间隔变化分别说明规则与比较基准。
- 单笔订单、单个截图不能直接判定“异常扣费”。

**验收**：月付 10 元与年付 120 元的每月等值一致；两个相似服务只显示候选，不擅自认定重复。

### 模块 5：个人风险总览

#### FR-501 统计口径

- 待处理：状态为进行中且存在未完成期限/行动的事项。
- 近期到期：用户确认且位于所选 7/30 天窗口内的期限。
- 潜在风险：满足已发布风险规则的事项，显示原因。
- 历史完成：具有完成记录的事项及结果。
- 节省金额：完成记录中用户明确确认的金额，按币种分别统计，不做无汇率依据的换算。
- 趋势：按周/月聚合实际期限、完成记录与风险暴露；数据不足时显示“样本不足”。

#### FR-502 可追溯

每个统计可点击回到产生它的记录列表；查询失败显示错误，不用 0 代替“统计不可用”。

**验收**：新增、修改、完成、恢复和删除记录后，所有相关统计按定义变化；演示模式开关不改变真实工作区数据。

## 8. 统一业务校验与异常处理

### 8.1 日期

- 日历日期统一为 `YYYY-MM-DD`，校验真实日期，包括闰年。
- `start_on <= end_on`；交易日期、截止日不合理时要求确认而非自动修正。
- 截止日按用户时区计算，默认 `Asia/Shanghai`；跨时区修改时提示对“今天”的影响。
- 衍生日期保存规则、来源日期、周期和单位，不允许前端任意时间字符串进入统计。

### 8.2 金额

- 内部使用最小货币单位整数和币种代码；不使用浮点累计金额。
- 默认非负；退款等方向由记录类型表达，不混用正负号。
- 拒绝非数字、指数记法、超出安全整数和超过币种小数位的输入。
- 不同币种分别展示，不静默相加。

### 8.3 重复与冲突

- 文件 SHA-256 用于发现完全相同材料；业务字段相似只生成重复候选，不自动合并。
- 创建操作携带幂等键；响应丢失时先查询原操作结果，不盲目重复写入。
- 编辑携带版本号；冲突时保留用户输入并展示最新版本，不静默覆盖。

### 8.4 空、错与加载

- 空数据：说明能做什么，提供上传/新建按钮。
- 无识别服务：明确“当前仅支持手工与规则解析”，不显示虚假进度。
- 部分字段成功：展示成功字段与待确认字段，不整批伪造失败或成功。
- 查询失败：保留现有数据并提示刷新；不能把失败结果显示为零。
- 上传/写入中禁用重复提交，但允许安全取消或离开并恢复任务状态。

## 9. 信息架构与 UX/UI 要求

### 9.1 页面

1. **首页 / 今日**：行动队列、近期时间轴、损失提醒、趋势和上传入口。
2. **材料 / 识别确认**：上传列表、处理状态、证据对照与字段确认。
3. **期限 / 时间轴**：30 天视图、全部期限、筛选和详情抽屉。
4. **事项详情**：证据、日期、风险解释、行动计划、完成时间线。
5. **订阅**：周期支出、即将续费、重复候选和实际扣款。
6. **记录 / 总览**：历史完成、用户确认节省额、可下钻统计。
7. **设置 / 数据**：时区、识别服务状态、导出、删除、隐私和演示模式。

### 9.2 视觉方向

- 设计主题：**“清晰的生活控制塔”**，以行动队列而非数据卡片墙为中心。
- 大面积暖白/浅灰背景，深色文字，主色采用沉稳青绿；橙红仅用于需要行动的期限。
- 8px 间距体系、适度圆角、细边框和轻阴影；不使用大面积渐变、霓虹光效或玻璃拟态堆叠。
- 中文使用系统无衬线字体，数字采用等宽数字特性；标题有层级但不过度营销化。
- 首页用一条主行动队列串联信息，图表只承担趋势和构成，不重复堆砌 KPI。
- 移动端优先保证上传、确认、今日处理和步骤勾选；不使用密集横向表格。

### 9.3 可访问性

- 所有操作可键盘完成，焦点可见，弹层有焦点管理。
- 正文与控件满足 WCAG AA 对比度；风险不只靠颜色，同时提供文字和图标。
- 表单有标签、错误定位和可读提示；图表提供文本摘要。
- 触控目标建议至少 44×44px，支持 200% 缩放和减少动态效果偏好。

## 10. 演示数据方案

- 演示工作区与真实工作区使用独立命名空间/存储，不共用统计查询。
- 固定包含：今日退货、3 天后续费、30 天内保修、一份退租计划、两个重复订阅候选、两条完成记录。
- 所有金额、日期和“节省”在演示环境中均明显标记为虚构样例，不回写真实工作区。
- 演示日期以用户首次进入演示时的日期为基准生成，避免过期；规则仍使用同一生产代码。
- 提供“重新载入”“清空演示”“退出演示”；上传私人材料前提示退出演示。
- 演示模式不能伪装调用 OCR/模型；若提供样本识别结果，明确标注“预置识别样例”。

## 11. 隐私、安全与合规

- 模型密钥、OCR 服务凭证和数据库凭证只在服务端；前端环境变量不得包含秘密。
- 每次数据和文件操作都根据服务端身份校验所有权，浏览器提交的用户 ID 和存储路径不可信。
- 默认仅将抽取所需文本发送给模型，优先脱敏订单号、地址、电话等无关信息；设置页展示处理边界。
- 不上传真实材料到公开演示环境；公开站点仍需应用级登录、权限与使用限制。
- 日志不记录原始材料、完整识别文本、签名 URL、密钥和模型密钥。
- 提供单条删除和全部数据清除；删除附件、数据库记录和待处理任务需一致处理并说明失败状态。
- 行动建议标注“基于你提供的信息，不构成法律或平台结果保证”。

## 12. 非功能需求

- **性能**：常规页面在竞赛演示网络下可交互；大文件显示真实进度和阶段，不阻塞其他页面。
- **可靠性**：写入可恢复、编辑有版本、重复提交不产生重复事项；失败不伪装成功。
- **可维护性**：识别、存储、模型、规则、统计各有独立边界，UI 不直接调用第三方服务。
- **可测试性**：时间、币种、ID、模型与存储均可注入固定测试实现。
- **兼容性**：验证当前 Chrome/Edge，移动端 Safari/Chrome 主流程；不支持能力明确提示。
- **容量**：首版以个人账户为范围，列表分页/游标加载，统计查询有界；具体配额以部署实测为准。

## 13. 发布验收主路径

1. 评委进入独立演示模式，能看到今日、近期、风险、趋势并完成一步行动。
2. 新用户上传一张真实订单截图或手工创建事项，字段缺失时进入待确认。
3. 用户修正并确认金额和日期，首页与时间轴立即出现对应事项。
4. 打开行动建议，勾选步骤、复制沟通文本，再提交完成记录。
5. 完成事项从当前待办移除，历史记录和用户确认节省额按输入更新。
6. 新建月付与年付订阅，检查每月等值、续费提醒和重复候选。
7. 上传重复文件、损坏 PDF、空图片、错误日期和超额金额，均得到可恢复反馈。
8. 刷新页面数据仍在；换账户无法访问前一账户材料；清除演示不影响真实数据。
9. 断开模型/OCR 服务，规则和手工闭环仍可用，界面准确标注能力状态。
10. 构建产物与网络请求中无模型密钥、数据库凭证和真实私人材料。
